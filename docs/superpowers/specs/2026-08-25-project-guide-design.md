# Гайд по проекту ServerMonitor — концепция

**Дата:** 2026-08-25
**Ветка:** feature/redesign

## Кому и зачем

Единственный читатель — автор проекта, который изучает бэкенд-разработку на C#/.NET и хочет
понимать **каждую строчку** своего кода, чтобы уверенно защищать проект на собеседовании.
Гайд — не документация продукта, а **учебник по собственному коду**.

Отдельный артефакт (пишется позже, отдельно) — README для GitHub: короткое описание
проекта, стек, скриншоты, запуск. Другой тон, другая аудитория. Гайд туда не входит.

## Принципы изложения

1. **С нуля.** Каждый термин объясняется при первом появлении: DI, middleware, миграция,
   пул потоков, tracking. Нельзя предполагать, что читатель знает слово «синглтон».
2. **Только настоящий код.** Все примеры — фрагменты из этого репозитория, со ссылкой на
   файл и строку. Никаких абстрактных `Foo`/`Bar`.
3. **Всегда «почему», а не только «что».** После каждого механизма — зачем он нужен, что
   сломается без него, какие есть альтернативы и почему выбрана эта.
4. **Честность о слабых местах.** Где в коде есть баг, упрощение или технический долг —
   так и написано, с объяснением, как делают в проде. Это ценнее приукрашивания.
5. **Схемы.** Потоки данных и жизненные циклы — диаграммами mermaid (GitHub их рисует).
6. **Язык — русский**, термины дублируются английскими (их видно в коде и в вакансиях).

## Структура

Файлы: `docs/guide/NN-slug.md`, индекс — `docs/guide/README.md`.

| Глава | Тема |
|-------|------|
| 00 | Карта проекта: четыре слоя, правило зависимостей, путь одного числа от железа до экрана |
| 01 | C# и .NET: язык на примерах нашего кода (типы, async/await, LINQ, generics, nullable, делегаты) |
| 02 | ASP.NET Core: хост, DI-контейнер, конвейер middleware, контроллеры, DTO |
| 03 | EF Core и PostgreSQL: DbContext, миграции, IQueryable и отложенное выполнение, трекинг |
| 04 | Фоновые сервисы: BackgroundService, конфликт времён жизни, IServiceScopeFactory, CancellationToken |
| 05 | Сбор метрик: /proc в Linux, P/Invoke в Windows, почему CPU считается дельтой |
| 06 | Blazor Server: рендер-режимы, SignalR, жизненный цикл компонента, JS-взаимодействие |
| 07 | Telegram-бот и алертинг: long polling, состояние, гистерезис |
| 08 | Конфигурация и запуск: appsettings, секреты, профили, порты |

Главы 09+ добавляются по мере развития проекта (агент, heartbeat, аутентификация, retention) —
каждый новый этап разработки завершается своей главой.

## Порядок работы

Сначала пишутся главы 00–08 по существующему коду (текущий этап), затем возвращаемся к
разработке. Каждая глава — отдельный коммит, чтобы можно было читать и править по частям.

## Критерии готовности главы

- Любой термин, встречающийся в главе, либо объяснён в ней, либо в предыдущей.
- Все ссылки на файлы/строки соответствуют реальному коду на момент написания.
- Есть хотя бы один блок «почему так» и упоминание альтернативы.
- Слабые места кода названы явно.
